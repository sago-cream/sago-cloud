# Oracle T3 coding

T3 runs as a separate Compose stack, with its own persistent state and workspace.
MiniSago releases replace only bot-core and the chat worker. Upgrading T3 is an
explicit `bun run deploy:t3` operation. The ARM64 image pins T3 0.1.6, verifies its
release checksum, and uses an immutable worker image for the coding toolchain.

The service runs as the unprivileged bun account. It shares the existing Codex
and GitHub auth volumes directly, so rotating credentials have one authoritative
file rather than copied refresh tokens. It receives no bot environment file,
Discord token, Docker socket, or operations checkout. Its deployment socket
still exposes only the bounded MiniSago immutable-commit protocol.

Deploy and expose the UI on a separate tailnet HTTPS port:

```bash
bun run deploy:t3
ssh sago-cloud 'sudo tailscale serve --bg --https=8443 http://127.0.0.1:3773'
```

Inspect `tailscale serve status --json` first. Port 8443 must be unused; preserve
existing port 443 handlers. The Compose port is loopback-only. The bot reaches
the service over the private Docker network; `MINISAGO_T3_WEB_URL` supplies its
user-facing HTTPS origin. Access from another computer requires tailnet access
and ordinary T3 authentication. Do not expose the server port publicly.

Register projects in T3 using the normal `t3 project` CLI or UI. Set each
project's model and permissions there. Additional repositories can be cloned
through the service's existing GitHub login and registered without changing
Sago's configuration. Keep old worker workspaces until unfinished tasks have
been preserved or transferred; T3 uses a separate workspace volume.

The bot uses a separate MCP OAuth grant saved only in bot-core state. After
starting T3 and configuring the bot endpoint, run `scripts/authorize-t3-bot` on
Oracle. It creates a fresh one-use local pairing code, completes native OAuth
with PKCE, verifies project access, and pipes the grant directly into the bot's
private state volume. Credentials never enter shell arguments or logs. Restart
bot-core afterward. The grant is revocable in T3's Sharing & access settings;
renew it with the same command when it expires, then revoke the older client
session. This is independent of the provider's Codex authentication.

Back up `sago_cloud_t3-state` as private runtime state and preserve
`sago_cloud_t3-workspace` for unfinished work. Both survive service replacement.
The bot's existing persistent state volume contains the OAuth/session grant and
Discord delivery checkpoints. Do not commit any of these volumes to Git.
